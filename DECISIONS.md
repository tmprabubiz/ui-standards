# Decisions

Tie-breaks and contested conventions, so agents and contributors do not re-argue them.

| # | Date | Question | Decision | Reason |
|---|---|---|---|---|
| 1 | 2026-10-01 | One file or many? | One skill; a short SKILL.md plus 13 family files loaded on demand | Keeps every-session cost to a few lines; agents load only matched families |
| 2 | 2026-10-01 | Tool-specific or neutral? | Agent Skills standard + thin adapters | One source works in Claude Code, Codex, Copilot and Cursor |
| 3 | 2026-10-01 | Clicking a mixed select-all | Resolves to "all on this page", never stays mixed | Matches Gmail and Outlook; predictable |
| 4 | 2026-10-01 | Selection when filters change | Clears | Avoids acting on items the user can no longer see |
| 5 | 2026-10-01 | Minimum password length | 15 when password is the only factor; 8 only when a second factor is always required; accept 64+ | NIST SP 800-63B Rev. 4 |
| 6 | 2026-10-01 | Payments | Approval-only; no entry in v1 | Legal and financial risk; always use a payment provider |
| 7 | 2026-10-01 | Index maintenance | Generated by script; validator fails if stale | Hand-kept indexes drift |
| 8 | 2026-10-01 | Research files | Kept local in `Research/`, gitignored | Raw model output; the catalogue is the condensed version |
| 9 | 2026-10-01 | Which catalogue loads first? | CORE-CARD, then target profile, then matched families | A desktop/local app should not inherit web/account assumptions; reduces routine context cost |
| 10 | 2026-10-01 | How to confirm a paid call? | Preview/estimate, then a separate cost-labelled Run action; do not stack generic warning dialogs | Owner can see scope and cost before committing; ledger prevents accidental repeats |
| 11 | 2026-10-01 | What is a desktop back end? | Local persistence and operations are first-class; no API or hosted service unless the app needs one | The owner's current app is local-first and single-user |
| 12 | 2026-10-01 | What does a slice approval cover? | Owner confirms a screen/slice walkthrough before its implementation begins | Matches incremental vertical-slice workflow and makes failure/recovery visible |
